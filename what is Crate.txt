Crate is an asset management and batch processing toolkit for Nuke. It runs as a native panel inside the application, designed for studios with shared pipelines and multiple artists working together.

Libraries let you browse shared asset collections through a thumbnail grid. Textures, plates, elements, Gaussian splats, 3D models. Thumbnails are generated automatically and cached to a shared location so the whole team benefits once they are built. Each library has a safe bin folder for recoverable deletion.

Cart is your personal collection. You can add assets from any Library, from Discover, or straight from the Nuke node graph. It persists across sessions, so you pick up where you left off. It also serves as a staging area for sending items to any of the processing panels.

Market lets you see what your teammates have collected. Every artist's cart is visible, so supervisors can check what people are working with, and artists can share reference or copy assets between carts without leaving Crate.

Discover is a folder browser for navigating directories and drives. It has a folder tree on the left, a detail list or thumbnail grid on the right, breadcrumb navigation, back/forward history, and file operations like rename, new folder, cut, copy, paste, and delete. It supports both regular folder paths and drive letter roots as branches. Discover is also where you access the 13 processing panels through the toolbar or right-click menus.

Templates gives you a browsable collection of Nuke script templates organised by category. Curators decide which templates are visible to the team.

Camera Database is a built-in reference for cinema camera sensor data.

Console shows you everything Crate is doing behind the scenes: engine detection, library loading, conversion progress, errors.

Settings is where Curators configure engine paths, access control, libraries, Discover branches, and everything else. Each engine has a test button so you can verify it works before going live. Curators can also lock and unlock Crate to control when the deployment is ready for artists.

Crate uses two roles. Curators have full access to everything: managing libraries, folders, templates, settings, and adding other curators. Visitors see only what has been published to them. Permissions control access to Discover, Cart, Templates, and file operations individually.

Crate relies on a set of external engines for its processing work. F3D generates thumbnails for 3D models and Gaussian splats. ImageMagick handles image thumbnails and contact sheets. MediaInfo extracts metadata for the status bar. FFmpeg handles video transcoding. OpenImageIO handles high-fidelity image conversion with OCIO colorspace support. Splat Transform is an npm package by PlayCanvas that converts between Gaussian splat formats: PLY, Compressed PLY, SOG, SPZ, KSPLAT, and GLB.

Graphs Analytics gives you a visual overview of Crate's status and highlights areas that might need attention.

There are 13 processing panels accessible from Discover. W-EXR and W-EXR-Q write EXR files with colorspace, rescale, and frame renumbering. W-MOV and W-MOV-Q encode MOV and MP4 files. SPLAT-C converts point clouds to Gaussian splats. W-GEO converts geometry between OBJ, FBX, Alembic, and USD with automatic texture relocation. IMG-C does batch image format conversion with OCIO colorspace management. CONTACT generates paginated contact sheets with a live grid preview. SEQ-C converts image sequences with two-dropdown colorspace control. W-4MAT reformats sequences and video through Nuke's Reformat node. BATCH renames files in place with six combinable operations, live preview, collision detection, automatic reverse-order processing for sequential renames, per-folder numbering, optional folder renaming, a progress bar, and undo. VID-C transcodes video with codec selection, aspect ratio handling, anamorphic de-squeeze, and custom resolution and frame rate. SCRIPT fans a single Nuke treatment out to many outputs.

All configuration lives in plain text files that are easy to read, edit, and version control. Delete operations go through bin folders so nothing is lost permanently.
